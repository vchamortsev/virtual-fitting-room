# Виртуальная примерочная

HTTP API для сайта небольшого fashion-магазина. Магазин присылает фото покупателя и карточку вещи, сервис возвращает картинку примерки.

Репозиторий проекта: https://github.com/vchamortsev/virtual-fitting-room

## Учебный прототип: какую гипотезу проверяем

**Ключевая гипотеза:** по фотографии человека и фотографии конкретной вещи можно локально получить новое изображение примерки через один пользовательский сценарий, без ручного монтажа и внешнего API генерации.

Это самая важная техническая неопределённость продукта. Прототип проверяет именно перенос одежды, а не весь будущий магазин, платежи или рост конверсии. Два связанных состояния интерфейса: загрузка исходных фотографий → очередь и обработка → новое изображение результата.

**Критерий проверки:** запрос с явно выбранной `fashn-vton-1.5` завершается успешно, возвращает новое изображение, а визуальная проверка подтверждает перенос выбранной одежды. Успешные тесты API, заранее сохранённая иллюстрация и режим `mock` отдельно этого не доказывают.

Пять секунд обработки — цель дальнейшей оптимизации, а не условие этой домашней работы и не достигнутый результат. Подбор размера, точная посадка, продажи и биллинг в эту проверку не входят. Покупать сервер или разворачивать облако для сдачи не требуется.

Для сдачи нужна **ссылка на публичный GitHub-репозиторий**. Локальная папка и презентация сами по себе это требование не закрывают. После публикации проверьте, что README и код видны в приватном окне браузера без входа в GitHub. Затем добавьте ссылку на платформу и в лист «Предзащита 2» таблицы курса.

Оба названных движка запускаются локально, веса не уходят на чужой сервер:

| Модель | Когда брать | Лицензия | Видеопамять |
| --- | --- | --- | --- |
| `fashn-vton-1.5` | витрина магазина | Apache-2.0 у весов примерки | около 8 ГБ |
| `catvton-flux` | проверка качества у себя | FLUX.1 [dev] только для некоммерческого использования | 24–40 ГБ |
| `mock` | отладка интеграции без видеокарты | код этого сервиса | не нужна |

Парсер человека внутри FASHN наследует лицензию NVIDIA SegFormer. Перед платным запуском прочитайте её отдельно: веса самой примерки это не отменяют, но зависимость стоит проверить.

`catvton-flux` выключен, пока в `.env` нет `ENABLE_CATVTON_FLUX=true`. Автовыбор модели его не подставляет.

## Запуск без видеокарты

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
pip install -r requirements.txt
copy .env.example .env
python -m uvicorn app.main:create_app --factory --host 127.0.0.1 --port 8080
```

Откройте http://127.0.0.1:8080/demo . Ключ по умолчанию: `local-dev-key`. В списке моделей выберите «Черновик интеграции».

Этот запуск проверяет только интерфейс и API. **Для демонстрации ключевой функции по заданию необходимо установить настоящую FASHN по следующему разделу и выбрать её в настройках демо.** `local-dev-key` — опубликованный учебный пример, не секрет и не ключ внешнего платного сервиса.

Проверка тестами:

```powershell
pip install -r requirements-dev.txt
pytest
```

Тесты API используют заглушку и не доказывают качество генерации. Один тест обёртки прогресса требует установленного пакета `fashn-vton`; без него этот тест пропускается явно.

Один процесс, без нескольких воркеров uvicorn: очередь примерки живёт в памяти процесса.

## FASHN VTON 1.5 локально

Нужно около 8 ГБ видеопамяти. На этом компьютере стоит Intel Arc, для неё ставьте сборку PyTorch XPU, не CUDA. На CPU модель тоже стартует, но одна примерка занимает минуты.

```powershell
pip install -r requirements-torch-xpu.txt
pip install --no-deps "fashn-vton @ git+https://github.com/fashn-AI/fashn-vton-1.5.git"
pip install -r requirements-fashn.txt
python scripts/download_fashn_weights.py --weights-dir weights/fashn-vton-1.5
```

Для NVIDIA вместо первого шага: `pip install torch torchvision --index-url https://download.pytorch.org/whl/cu124`. Пакет `fashn-vton` сам тянет `onnxruntime-gpu`, поэтому он ставится с `--no-deps`, а `onnxruntime` берётся из `requirements-fashn.txt`.

В запросе укажите `model=fashn-vton-1.5` или уберите поле: при `DEFAULT_MODEL=auto` сервер сам возьмёт FASHN, если веса на месте.

Категории: `tops` (верх), `bottoms` (низ), `one-pieces` (платье, комбинезон). Фото вещи: `flat-lay` для карточки товара на ровном фоне, `model` если вещь надета на человека. Для магазинного каталога обычно `flat-lay`.

`num_timesteps`: 20 быстрее, 30 обычный режим, 50 выше качество. `guidance_scale` для FASHN около 1.5.

### Воспроизводимая проверка настоящей генерации

После установки FASHN и весов выполните из корня репозитория:

```powershell
python scripts/verify_real_tryon.py --steps 20 --timeout 1200
```

Скрипт отправляет демо-фото в API приложения с явно выбранной FASHN, ждёт новое задание и сохраняет `docs/evidence/real-tryon.png` и `docs/evidence/real-tryon.json`. В отчёте указаны устройство, параметры, время холодного запуска и контрольные суммы. Подмены на `mock` нет: ошибка модели завершает проверку ошибкой. Первая генерация может занимать существенно дольше последующих; это не тест производительности.

Без сети проверка возможна, если заранее скачаны и веса примерки, и кеш парсера человека. Для этого перед запуском можно задать `$env:HF_HUB_OFFLINE='1'`. В противном случае загрузка необходимых весов потребует интернета. Фотографии обрабатываются локально.

## CatVTON-FLUX локально

Это склейка карточки вещи и фото человека в один холст и дорисовка области одежды моделью FLUX Fill с LoRA CatVTON. Маска строится сама (SegFormer по одежде) либо приходит файлом `mask_image`: белым отмечено то, что нужно заменить.

Лицензия FLUX.1 [dev] не разрешает коммерческую витрину и выдачу результата покупателям. Для магазина оставьте движок выключенным, пока не будет отдельной лицензии Black Forest Labs. Веса LoRA тоже распространяются с пометкой non-commercial.

Включение только для своей проверки:

```powershell
pip install -r requirements-torch-xpu.txt
pip install -r requirements-catvton.txt
```

На NVIDIA вместо первой строки используйте индекс `cu124`. FLUX в bf16 занимает около 24 ГБ, на Intel Arc 16 ГБ эта модель не помещается.

В `.env`:

```
ENABLE_CATVTON_FLUX=true
HF_TOKEN=hf_...
```

На Hugging Face нужно принять условия `black-forest-labs/FLUX.1-dev` и `black-forest-labs/FLUX.1-Fill-dev`. Первая примерка скачает десятки гигабайт. `CATVTON_OFFLOAD=true` держит модель по частям, чтобы влезть в 24 ГБ; на 40 ГБ offload можно выключить. Шаги по умолчанию 30, `guidance_scale` 30.

Запрос: `model=catvton-flux`.

## Контракт для бэкенда магазина

Ключ передавайте с сервера магазина, не из браузера покупателя.

`POST /v1/try-on`, `multipart/form-data`, заголовок `X-API-Key`.

| Поле | Обязательно | Смысл |
| --- | --- | --- |
| `person_image` | да | фото покупателя, JPEG/PNG/WebP, до 12 МБ |
| `garment_image` | одно из двух | файл карточки вещи |
| `garment_url` | одно из двух | ссылка на страницу товара или прямо на фото. Сервер берёт картинку из JSON-LD / Open Graph |
| `category` | нет | `tops`, `bottoms`, `one-pieces` |
| `garment_photo_type` | нет | `model` или `flat-lay` |
| `model` | нет | `fashn-vton-1.5`, `catvton-flux`, `mock` |
| `mask_image` | нет | маска для CatVTON |
| `seed` | нет | целое, по умолчанию 42 |
| `num_timesteps` | нет | 10–60 |
| `guidance_scale` | нет | 0–50, свой разумный уровень у каждой модели |
| `segmentation_free` | нет | `true` или `false`, для FASHN |
| `webhook_url` | нет | куда POST-ом прислать итог |
| `wait_seconds` | нет | 0–120, держать соединение, пока примерка не кончится |

Ответ `202`, если примерка ещё идёт, и `200`, если за время ожидания уже есть итог:

```json
{
  "id": "job_…",
  "status": "queued",
  "model": "fashn-vton-1.5",
  "result_url": null
}
```

Дальше `GET /v1/try-on/{id}` тем же ключом. Когда `status` равен `succeeded`, заберите PNG по `result_url`. Чужой ключ это задание не видит. Файлы старше `RETENTION_HOURS` удаляются.

Список моделей: `GET /v1/models`. Живость процесса: `GET /health`.

Пример:

```powershell
curl.exe -X POST http://127.0.0.1:8080/v1/try-on ^
  -H "X-API-Key: local-dev-key" ^
  -F "person_image=@person.jpg" ^
  -F "garment_image=@garment.jpg" ^
  -F "category=tops" ^
  -F "garment_photo_type=flat-lay" ^
  -F "model=fashn-vton-1.5" ^
  -F "wait_seconds=120"
```

Описание схем также открыто на http://127.0.0.1:8080/docs .

Docker-образ в репозитории ставит только API и черновик. Веса FASHN и CUDA-пакеты подключайте томом `./weights` и отдельной установкой, как выше. `docker compose up --build` читает `.env`.
